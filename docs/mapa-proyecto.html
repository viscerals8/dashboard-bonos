Sistema de Bonos — dashboard-bonos

Aplicación de analítica de bonos por trabajador/zona/empresa. Stack: Angular 20 (standalone) + TailwindCSS en el frontend, FastAPI + SQLAlchemy en el backend, sobre SQL Server.

Angular 20 TailwindCSS ng-apexcharts FastAPI SQLAlchemy (raw SQL) SQL Server · pyodbc

Resumen

  • Es una app de un solo caso de uso: un ranking "Top 10 de bonos por trabajador", con filtros por zona/año/mes/semestre y export a Excel.
  • El backend expone un solo endpoint de datos (/dashboard/bonos-top) que corre una consulta SQL compleja (CTE + ROW_NUMBER()) directamente contra SQL Server — no hay ORM con modelos, ni capa de schemas.
  • El frontend recibe el dataset completo y hace todo el filtrado/agrupado en el navegador (no hay paginación ni filtros server-side).
  • Hay una carpeta raíz (src/app y package.json en dashboard/) que parece un scaffold Angular abandonado, separado del proyecto real dashboard-bonos/. Ver observaciones.

Observaciones

Credenciales de base de datos hardcodeadas
database.py tiene usuario/contraseña (sa/afm) y la IP del servidor escritos directo en el código, versionados en el repo. Deberían moverse a variables de entorno / .env.
Endpoints sin autenticación
Cualquiera con acceso a la red puede pegarle a /dashboard/bonos-top y ver montos y nombres de trabajadores.
Carpeta raíz duplicada / residual
dashboard/src/app/services/dashboard.service.ts está vacío y el package.json de la raíz solo trae Tailwind — parece un ng new inicial que quedó abandonado cuando se creó dashboard-bonos/. Si no se usa, vale la pena borrarlo para no confundir a quien retome el proyecto.
Sin gestión de dependencias del backend
No hay requirements.txt ni pyproject.toml — solo la venv/ versionada. Difícil de reproducir el entorno en otra máquina.
Filtrado en el cliente, no en el servidor
El endpoint trae todo el histórico de bonos pagados y el componente Angular agrupa/filtra/top-10 en el navegador. Funciona con el volumen actual, pero no escala si la tabla INGRESO_BONO crece mucho.

Si sigues avanzando el proyecto

  1. Mover credenciales de database.py a variables de entorno y sacar la venv/ del control de versiones (.gitignore).
  2. Decidir si la carpeta raíz (dashboard/src, package.json) se mantiene o se elimina — hoy convive con dashboard-bonos/ sin motivo claro.
  3. Congelar dependencias del backend con pip freeze > requirements.txt.
  4. Si el dataset crece, mover el filtrado (zona/año/mes/semestre) a parámetros de query en el endpoint en vez de traer todo al navegador.
